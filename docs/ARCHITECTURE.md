# Architecture

> Current state: all parts in the table below are built. The CI workflow and the release workflow exist. Version
> 0.1.0 is released.

## Overview

```
Rex init.lua -- require("annorex").setup{} --> annorex.lua
                                                 | custom actions: annorex_last, annorex_files
                                                 v opens a full-window layer
                                   +-----------------------+
                                   | annorex (Rust binary) |--> rex CLI (JSON on stdin)
                                   +-----------------------+--> agent transcripts (read-only)
```

Annorex has two parts:

1. Lua module (`annorex.lua`, built). Rex does not have a plugin system. Rex has custom actions in its Lua
   configuration file. The module registers the actions `annorex_last` and `annorex_files`. An action runs
   `annorex rex open last` or `annorex rex open files` with `--target BLOCK --session SESSION` and a
   timeout of 25 seconds. It reports the first line of an error. Rex runs actions with a short `PATH`, so the
   module finds the binary itself: the `bin` option, else the path that `annorex rex install` wrote into the module,
   else the cargo, Homebrew, and `~/.local/bin` places. If `annorex rex open` exits with code 5, the focused pane is not
   an agent. The module then runs `annorex rex agents` and picks the pane, as the Agent picker row describes. The
   module has only this logic.
2. Rust binary (`annorex`, built). The binary does all other work. It uses only the `rex`
   command-line tool to communicate with Rex. It sends the arguments as JSON on standard input. It never opens a
   network port.

## Components

|--------------------|-------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Rex adapter        | Built | Runs `rex block call -s SESSION -b BLOCK METHOD -` and `rex api call -s SESSION METHOD -` with the arguments on standard input. Gives typed results for the process, program status, terminal modes, and size of a pane, and for the session view. Creates, minimizes, and closes layers, and focuses blocks. Finds `rex` in `REX_BIN_DIR`, then as the executable of the parent process (a Rex action), then in `PATH`.                                                                                                                                                                                     |
| Agent detection    | Built | Identifies Claude Code, Pi, OpenCode, or Codex CLI from the `app` of the root program status record, when the foreground process confirms it. Otherwise uses `argv0` of the foreground process.                                                                                                                                                                                                                                                                                                                                                                                                              |
| Dialog test        | Built | Refuses a send when the root program status is "blocked" (a permission, question, or authentication dialog). Also refuses when the agent process does not own the root status record ("the agent has not reported its state yet"). A busy agent can get a message.                                                                                                                                                                                                                                                                                                                                           |
| Payload            | Built | Removes escape characters and control characters. Keeps line feeds and tabs. Puts the text in one bracketed paste.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Delivery           | Built | Reads the status two times and refuses on a dialog or on another owner of the status record. Pastes the text, waits 300 ms, reads the status again, and sends Enter. | Transcript readers | Built | Find the session of an agent and read its recent messages. Adapted from plannotator-tui (MIT). It keeps only the final answers (`phase: final_answer`, or no phase) and the prompts.                                                                                                                                                                                                                                     |
| Install            | Built | `annorex rex install` writes `annorex.lua` beside the `init.lua` of Rex. It refuses to replace a file that it did not write. | Placement          | Built | `annorex rex open last` and `annorex rex open files` look for a block with the label `Annorex review · block:<id>` in the session view. The labels `annorex:` of v0.2.0 and `annorex-files:` of older versions are still found. The agent block id is last in the label. If one exists, they raise and focus its layer (one Annorex for each session). Otherwise they create a floating layer over the full window of the agent with `session.new_layer`. If two calls race, the newest layer closes.                                                                                                        |
| Reply loading      | Built | Finds the session of the agent: Claude Code by its process ID, Pi, OpenCode, and Codex CLI by the directory. Shows a session picker when more than one session can belong to the agent. Reads the 25 newest replies.                                                                                                                                                                                                                                                                                                                                                                                         |
| Document model     | Built | Shows Markdown with pulldown-cmark (headings, lists, quotes, code, tables, rules). Keeps a map from each displayed line to its source byte range and source line number. Keeps the cells of each table, so that `wrap.rs` can reflow a table that is wider than the window. Shows inline math (`$...$`) as plain text, with a map of common symbols (for example `\rightarrow` as an arrow). The stops, the offsets, and the quote of a math span stay the raw source. Keeps the blank line between the items of a loose list. A blank line is never part of a block.                                        |
| Wrapping           | Built | Wraps the document at the display width of each character cluster. Keeps the wrapped lines in a cache for each width.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Layout             | Built | Calculates the areas again for each frame. A header row and a footer row. From 100 columns and 16 rows: the tree on the left (28 columns, when the view has files and the tree is open) and the document. From 120 columns: the card rail (34 columns) directly right of the document. The document takes all the width that is left, with its margin and gutter. Below 100 columns or 16 rows: one column, and the tree and the lists open over the document. "pane too small" below 40×10.                                                                                                                 |
| Block model        | Built | `doc.rs` marks the blocks of a document: heading, paragraph, list item (own text only), whole code fence, whole table, whole quote, and rule. A plain text file has one block for each group of lines between blank lines. Each block has a source range and a range of display lines.                                                                                                                                                                                                                                                                                                                       |
| Focus and modes    | Built | `ui/focus.rs`. Block mode and text mode. In block mode, at the start no block has the focus, and the mode is `Browse`. `j` or `k` or a click chooses a block. Then one block has the focus. `j` and `k` go from block to block, and scroll inside a tall block. Text mode has a free cursor and a selection. Note keys act on the whole block in block mode, and on the selection or the cursor line in text mode.                                                                                                                                                                                           |
| Hit map            | Built | `ui/hits.rs`. Each frame records the rectangle of each block, text cell, button, card, tree row, list row, and footer hint. The mouse uses it for hit tests and for the wheel. The keys scroll with the wrapped rows of the document, not with the hit map. The next frame rebuilds it.                                                                                                                                                                                                                                                                                                                      |
| Mouse path         | Built | `ui/mouse.rs`. `handle_mouse` returns an `Effect`, as `handle_key` does. A click finds its target in the hit map of the last frame, compares the id with the state, and calls the code of the matching key. A drag selects text in text mode. The wheel scrolls the part under the pointer. A question and the find input take no mouse event. The terminal loop turns on mouse capture.                                                                                                                                                                                                                     |
| Action bar         | Built | `ui/bar.rs`. One row above the focused block or the selection. When no row is free above, it uses the row below. When no row is free there, it uses the top row of the text area. It has a chip for each note type: looks good, comment, remove, and replace. A chip has a bright black background. Its key is bold in the color of the note. The space between chips has no background. No bar shows without a focus.                                                                                                                                                                                       |
| Cards and markers  | Built | `ui/cards.rs`. The notes show in the card rail from 120 columns, and as a dot in the note color in the right margin at narrower widths. A numbered list picks one note when several share a place. When a card would pass the bottom of the rail, it moves up. When the cards do not fit, the rail leaves out the top cards first.                                                                                                                                                                                                                                                                           |
| Note box           | Built | A floating box below the block (above when there is no room) with the buttons `save` and `cancel`. It shows 8 rows of text and scrolls. `shift+enter` needs the keyboard enhancement of the terminal.                                                                                                                                                                                                                                                                                                                                                                                                        |
| UI                 | Built | ratatui screens: the document with the header (the send button) and a footer for each mode, the centered boxes (reply list and finder), the session picker, the help screen, and errors. The same screens work in a second mode for files: the tree, the fuzzy find, and the change banner. Plain text files have a line number gutter. Markdown has none. A resize keeps the top line.                                                                                                                                                                                                                      |
| Terminal loop      | Built | `annorex last` and `annorex files`. Waits a maximum of 250 ms for an event, applies all queued events, and draws one time. A mouse press after an earlier event of the same batch first draws, so the click uses the new hit map. A batch of only pointer moves draws nothing. Stops on `q`, on SIGHUP, SIGTERM, or SIGINT, or when the terminal input ends. Reads the agent state every 2 seconds on a thread.                                                                                                                                                                                              |
| Agent picker       | Built | `agents.rs`. `annorex rex agents --session SESSION` prints the agent panes of the session as JSON. Each pane has `block_id`, `agent`, `title`, `subtitle`, and `detail`. With no agent pane, the action fails. With one, it opens that pane. With two or more, it asks in the command palette ("Annorex: pick the agent"). Then it focuses the chosen pane and opens. A cancel closes the question with no message. |
| Commands           | Built | `annorex probe`, `annorex deliver`, `annorex last`, `annorex files`, `annorex update`, `annorex rex install`, `annorex rex open last`, `annorex rex open files`, and `annorex rex agents`.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Update check       | Built | `update.rs`. Asks `/usr/bin/curl` for `GET https://api.github.com/repos/devararishivian/annorex/releases/latest`. It runs in the background, at most once each 24 hours. | Module refresh     | Built | At each `annorex rex open`, replaces `annorex.lua` when its version differs. It replaces only a file with the module marker. | Configuration      | Built | Reads `config.toml` (`enter_delay_ms`, `labels`, `changes_turns`, and `[keys]`). Rejects an unknown key. A bad file gives exit code 64.                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Keys               | Built | Maps each key to an action. Fixed keys cannot be bound. Rejects a key that two actions use.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Review             | Built | Keeps notes (looks good, comment, remove, replace) on source byte ranges. Each note has a send time. Exports the notes as Markdown with a fence longer than any backtick run in the quote. For many documents, the export has one section for each: the replies first, then the files in the order of opening.                                                                                                                                                                                                                                                                                               |
| Drafts             | Built | Saves one JSON file for each reply or file after each change, in an atomic write. Keeps an unreadable file. After a finished send, it deletes the sent notes and the empty draft, and it keeps work in progress. A paste or a held Enter keeps the notes as sent. At start, it deletes drafts that a finished send used up and drafts with no note. It never deletes a draft that only a paste or a held Enter marked. Moves a quote again when the text moved. Marks it "text not found" if it is gone.                                                                                                     |
| Send               | Built | `S`, `M`, and `P` call delivery with the export. A send gives only the notes that no send took. Sets `sent_at` in memory after a send.                                                                                                                                                                                                                                                                                                                                                                        |
| Clipboard          | Built | `Y` writes an OSC 52 sequence and runs `pbcopy`. Reports when only the terminal part worked.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Files              | Built | Scans the work directory breadth first. Ignore files have no effect. Hidden files show only after `.`. Build and version-control folders never show. It follows no links and lists 20,000 entries at most. Makes sure that a path is inside the root, also through links. Loads a file up to 1 MiB and refuses binary data.                                                                                                                                                                                                                                                                                  |
| Fuzzy find         | Built | Ranks paths with its own scorer: a subsequence match with bonuses for word starts and for consecutive letters. At most 200 results.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| One document list  | Built | `App` has one list of documents: the replies (newest first), then the open files. Each open file has the id `file:PATH`. A problem with the reply session (`ReplySource::Missing` or `Pick`) shows in the reply list and does not block the files. One export and one send cover all documents. The key of a draft uses the session of the agent for a reply and the work directory for a file. Markdown files show as Markdown, other files as plain text. At most 50 files are open.                                                                                                                       |
| File tree          | Built | A panel with the directories, the filter, and the marks for files with unsent drafts. The scan runs on a thread.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Changed files      | Built | `annorex-hosts` reads the successful file-changing tool calls of a transcript (`changes`, `claude::changes`, `pi_changes`, `opencode_changes`, `codex_changes`, and OpenCode in both table families). `codex_changes` reads the completed `FileChange` items of Codex. It does not list a declined change or a shell edit. `changes.rs` makes the paths relative to the work directory and a thread polls every 2 seconds. The tree puts the files first and a banner counts the new ones.                                                                                                                   |
| New reply banner   | Built | A thread compares the size and the time of the transcript every 2 seconds. When they change, it reads the replies and sends the id of the newest one. The viewer shows a banner when that id is not its own newest reply. `r` and a new read clear it. While the user must choose a session, nothing is watched.                                                                                                                                                                                                                                                                                             |
| File watch         | Built | A thread compares the size and the time of each open file with the values at the last read, every 2 seconds. The viewer shows a banner and places the notes again after `r`.                                                                                                                                                                                                                                                                                                                                                                                                                                 |

## Crates

- `annorex-hosts` (built): the adapted transcript readers. This crate is separate, so the license boundary is clear.
- `annorex` (built): a library and a binary for all other parts. The Lua module is in `crates/annorex/lua/`.

## Key constraints

- Rust 1.99.1, edition 2024, ratatui 0.30.2, crossterm 0.29.0. The Lua version in Rex is 5.1.
- A Rex custom action must finish in 30 seconds. Thus, the Lua module only opens the pane.
- A pane that Rex creates gets its data from command-line arguments. It does not get environment variables from the
  layout.

## Build, CI, and release

- CI (`.github/workflows/ci.yml`, built). It runs on each push and each pull request to `main` and `develop`. It runs
  on a macOS runner with Rust 1.99.1. It runs `cargo fmt`, `cargo clippy` with warnings as errors, `cargo test`, and
  `cargo deny check licenses sources bans`. `deny.toml` lists the allowed licenses and sources. It also runs
  `cargo deny check advisories`. A new advisory gives a warning, not a failure.
- Release (`.github/workflows/release.yml` and `dist-workspace.toml`, built). cargo-dist 0.34.0
  makes the workflow. A tag with a version number, for example `v0.1.0`, starts it. It builds the binary for
  `aarch64-apple-darwin` and `x86_64-apple-darwin` and puts the archives on a GitHub release. On a pull request, the
  workflow only makes the release plan and publishes nothing.
- Installers of the release (built). A shell installer puts the binary in `$CARGO_HOME/bin`, else in
  `~/.cargo/bin`. A Homebrew formula goes to the tap `devararishivian/homebrew-tap` and puts the binary in the
  Homebrew `bin` directory. The Lua module finds the binary in both places.
- Source formula (`packaging/homebrew/annorex.rb`, built). It builds Annorex from the source archive of a tag with
  `cargo`, with the update check turned off. CI checks it with `brew style`.
- Install methods: the shell installer, the Homebrew tap formula `devararishivian/tap/annorex`, and `cargo install` from
  the source.
